# 测试说明

## 1. 运行方式

```bash
npm install
npm test            # Vitest，50 个用例，约 2 秒，全部离线（演示数据客户端 + 可控故障注入）
npm run typecheck   # TypeScript 严格模式
npm run build       # 生产构建
```

CI：`.github/workflows/deploy.yml` 在每次推送 `main` 时先跑测试与构建，通过后才发布到 GitHub Pages。

测试使用内存存储（`MemoryKV`）与演示数据客户端（`FuyaoDemoClient` 时延 1ms、重试退避 0ms），通过 `settings.faults` 注入故障，通过 `ScriptedLlm` 模拟 LLM 的正确/错误/违规/异常输出。

## 2. 用例矩阵

### 2.1 主链路（`tests/main-flow.test.ts`，10 个）

| 场景 | 断言要点 |
|---|---|
| 个股研究全流程 | 两阶段规划展开 11 类工具；证据含来源/单位/时点/状态；计算证据含公式与 2 条上游证据；事实结论均有证据；资讯缺失列为不确定；写记忆经审批；Markdown 含证据附录 |
| 拒绝写记忆 | 记忆任务 skipped，报告仍在，记忆中无笔记 |
| 同业对比 + 冲突 | 比亚迪指标与报表推算冲突被标记；冲突值不参与排序；行情批量一次请求 |
| 市场情绪 | 封板率字段由小数 ×100 展示；资讯缺失 → 不确定 |
| 持仓体检（批准） | 敏感读取审批；第一大持仓 30%；调和加权 PE > 0 |
| 持仓体检（拒绝） | 不读取持仓，输出“未授权”说明，运行完成 |
| 板块观察 | 检索 → 成分股 → 批量行情估值，计划展开 2 次 |
| 线程追问 | 省略标的时沿用线程实体，并命中缓存 |
| 超预算审批 | 三只股票对比需预算审批；拒绝后 0 次工具调用 |
| 未识别标的 | 不调用数据接口，输出澄清说明 |

### 2.2 数据缺失 / 接口失败（`tests/failure.test.ts`，11 个）

| 注入 | 期望行为 |
|---|---|
| 行情服务错误 | 任务失败、证据记 `error`；不出现“最新价”事实，出现“行情未获取”不确定结论；数据质量区列出失败 |
| 首次 429 限流 | 自动重试成功，attempts=2，retries≥1 |
| 估值接口超时 | 重试耗尽 → 降级为静态 PE，口径注明“不可直接比较”，结论为推断，记入降级记录 |
| 利润表返回空 | 证据 `missing`，财务结论为不确定 |
| 行情数据过期 | 证据 `stale`，引用它的结论自动降级为不确定 |
| 最新报告期无数据 | 财务指标降级到上一期年报，口径中注明 |
| iFinD 资讯失败 | 降级为扶摇快讯；无真实内容时声明“不做归因” |
| 全部鉴权失败 | 立即鉴权熔断 → stopped → 部分报告，0 条事实 |
| 连续失败 | 达阈值熔断 → 部分报告 |
| 工具调用预算耗尽 | 停止规则触发 → 部分报告；放宽预算 ×2 后继续推进 |
| 参数非法 | 参数校验失败，不发起调用（attempts=0） |

### 2.3 极端与合规边界（`tests/compliance.test.ts`，7 个）

| 场景 | 断言要点 |
|---|---|
| “茅台明天会涨吗？现在能买吗？” | 识别预测+买卖诉求，改写为证据研究，仍按个股研究执行；报告含合规提示、不含违规表述 |
| 荐股/收益承诺识别与误报 | “推荐一只稳赚的股票”被识别；“该公司持有大量现金吗”不误报 |
| 内幕消息 | 直接拒绝，0 次工具调用 |
| 输出审查 | “建议买入/将大幅上涨/稳赚”被移除并记录 3 处 |
| 结论分级 | 无证据/缺失/冲突/过期 → 不确定；计算证据 → 推断 |
| 多类型报告 | 全部带免责声明且通过输出审查 |
| 极端值与不适用指标 | 银行/保险毛利率为 null → 缺失，不参与比较 |

### 2.4 状态管理（`tests/state.test.ts`，9 个）

检查点保留 15 个；运行中停止后继续执行（已完成任务不重复）；停止后生成部分报告；**模拟崩溃**（新运行时读取持久化状态）→ `interrupted` → 续跑完成；回滚到检查点（证据数量与快照一致、产物清空、状态暂停）后重新执行；上下文压缩（摘要保留证据 ID、pinned 不丢）；记忆（敏感项不自动注入、研究笔记按标的召回、30 天过期标注、同标的更新不重复）；观测（工具/规划/审批/检查点/合规/记忆 span 完整）。

### 2.5 LLM 与适配器（`tests/llm-and-adapters.test.ts`，13 个）

LLM 规划合法 → 采用并计费；非法 JSON/越界意图 → 回退规则；摘要编造数字 → 校验不通过回退模板；摘要含“建议买入” → 合规拦截回退；数字与证据一致 → 采用；LLM 故障注入 → 规划与摘要都回退且运行完成；`verifyNarrative` 单位换算与失败情形。扶摇信封错误码映射；Live 客户端请求头/参数拼接/无 Key/429/网络错误；iFinD MCP 客户端 initialize → tools/call、SSE 解析与会话 ID；规则规划的意图分类、代码后缀推断、长名优先、线程追问。

## 3. 对真实服务的验证（非自动化）

| 检查 | 结果 |
|---|---|
| 扶摇 CORS 预检（Origin=github.io，请求头 x-api-key） | 返回 `Access-Control-Allow-Origin` 回显与 `Access-Control-Allow-Headers: x-api-key`，浏览器可直连 |
| 缺失 Key | `{"code":2003,"message":"Missing X-api-key"}`（文档写 2001，已兼容） |
| 无效 Key | `{"code":2003,"message":"Invalid or revoked API key"}` |
| 实时模式 + 无效 Key 跑“研究贵州茅台” | 首个鉴权失败后熔断 → stopped，报告 4 条结论全部为“不确定”，无任何事实结论 |
| 有效 Key 端到端 | **未验证**（无可用 Key），见 README“已知边界” |

## 4. 手工验收清单（在线页面）

1. 点左侧示例「研究贵州茅台的基本面和估值」→ 观察计划逐项执行 → 报告出现后点击任一 `E-xxx` 芯片，右侧证据面板定位到该证据（来源/字段/口径/时点/原始记录）→ 批准“写入长期记忆”→ 「记忆」面板出现研究笔记。
2. 「比较宁德时代和比亚迪的盈利能力」→ 表格中比亚迪“归母净利同比”带 ⚠，结论区出现“数据冲突”。
3. 「工具/故障演练」把 `valuation_snapshot` 设为“超时”，再研究一只股票 → 计划中估值任务显示“降级”，KPI 显示“静态PE(降级)”。（超时约需 8 秒×3 次）
4. 把 `price_snapshot` 设为“数据过期” → 最新价结论变为“不确定”，数据质量区显示“数据过期”。
5. 研究进行中点「■ 停止」→「从检查点继续」或「生成部分报告」；或在「检查点」面板点「⚡ 模拟崩溃」→ 刷新后顶部横幅「从检查点恢复」。
6. 「检查点」面板选择任一检查点「回滚到此」→ 运行变为“已暂停”，再继续执行。
7. 「设置」把上下文上限调到 300 → 「上下文」面板出现压缩摘要与压缩记录。
8. 「对比茅台、五粮液和美的集团」→ 先出现预算审批卡片。
9. 「茅台明天会涨吗？现在能买吗？」→ 顶部出现合规改写提示，报告无预测与买卖建议。
10. 「帮我体检一下我的持仓」→ 拒绝授权 → 输出“未授权”说明。
