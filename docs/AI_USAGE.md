# AI 使用与验证记录

## 1. 使用的 AI 工具

| 工具 | 用途 |
|---|---|
| Claude Code（Claude 桌面应用 Code 模式，模型 Claude Opus 5.5） | 阅读题目与数据源文档、产品与架构设计、编写全部代码/测试/文档、在内置浏览器中做界面走查、运行测试与构建 |

产品本身**不依赖** LLM 运行（规则引擎兜底）；可选接入的 LLM 只用于意图理解与摘要写作，见 README 第 5 节。

## 2. AI 参与的环节

| 环节 | AI 做了什么 | 人工把关点 / 验证方式 |
|---|---|---|
| 需求拆解 | 把题目拆成“Harness 机制清单 + 投研产品体验清单 + 交付物清单”，逐项映射到模块（README 第 3 节表格） | 对照题目原文逐条核对是否有实现与测试 |
| 数据源调研 | 读取扶摇 `llms-full.txt` 与 iFinD `llms-full.txt`，抽取端点、参数、字段、单位、错误码 | **对真实服务发请求核对**（CORS、鉴权错误码），发现文档与实际不一致（见下） |
| 架构设计 | 纯前端 Harness（浏览器直连数据源，Key 不出浏览器）+ 规则规划兜底 + 可选 LLM | 关键取舍：LLM 不产生数字；演示数据必须显式标注；任何异常不得静默产出“正常”结论 |
| 编码 | 核心运行时、工具注册、适配器、报告与合规、React 界面 | TypeScript 严格模式、`tsc --noEmit`、50 个自动化用例、浏览器手工走查 |
| 测试 | 设计主链路/失败降级/状态恢复/合规边界/LLM 校验/适配器用例 | 用例先行暴露了多个真实缺陷（见下） |
| 文档 | README、测试说明、本记录、演示脚本 | 内容与代码行为交叉核对（如端点路径、用例数量） |

## 3. 验证过程中发现并修正的问题

以下问题均由自动化测试、对真实接口的探测或界面走查发现，并已修正、加了回归用例：

| # | 问题 | 如何发现 | 修正 |
|---|---|---|---|
| 1 | **文档与实测不一致**：扶摇文档称缺失/无效 Key 返回 `code=2001`，实测两者都返回 `code=2003`（message 分别为 `Missing X-api-key` / `Invalid or revoked API key`）。原实现会把它误报为“无权访问该能力” | 用 curl 直接请求真实接口 | 2001/2003 统一按鉴权错误处理并透出服务端 message |
| 2 | 合规改写后的目标文本（含“…与风险因素…”等说明）被送进实体解析，残余词被当成标的，“茅台明天会涨吗？能买吗？”被误判为**对比研究** | 合规用例失败 | 合规模块分离 `parseGoal`（纯净目标）与 `effectiveGoal`（展示用），解析只用前者；停用词补充“现在/目前/今天” |
| 3 | 荐股识别正则窗口过窄，漏判“推荐一只稳赚的股票” | 合规用例失败 | 放宽匹配窗口 |
| 4 | 买卖建议正则过宽（含单字“该”和“持有”），会误报“该公司持有大量现金” | 设计误报用例 | 收紧为“应该/能/可以…买卖类动词”，加反例测试 |
| 5 | 时间显示使用 `toISOString()`（UTC），K 线末日显示为前一天 | 浏览器走查时发现“日 K 截止 11-16”与快照“11-17”不一致 | 全部改为北京时间格式化；年报期推断也按 UTC+8 计算 |
| 6 | 用户**拒绝**读取持仓后，计划无法展开，运行以“失败：报告未生成”结束，用户得不到任何解释 | 设计“拒绝授权”用例 | 调度器在计划终结且无报告任务时自动补一条说明性报告任务；持仓未授权给出专门说明 |
| 7 | 鉴权失败后仍逐个调用其余工具（实测 6 次无效请求才熔断），浪费配额 | 用无效 Key 对真实接口跑实时模式 | 增加“鉴权失败立即熔断”，停止原因提示检查 Key；恢复时清除熔断状态 |
| 8 | 侧栏示例按钮使用旧闭包，可能把新研究追加进当前线程 | 代码审读 + 走查 | `send(goal, forceNew)` 显式新建线程 |
| 9 | 资讯占位证据被列入“字段缺失”结论，文案冗余 | 走查报告 | 资讯缺失单独成条（“不做归因”），不重复列出 |
| 10 | 移动端顶栏溢出、线程列表元信息竖排 | 375px 视口走查 | 响应式隐藏次要文字、增加菜单按钮、省略号截断 |
| 11 | “连续失败熔断”用例最初设定不合理：中间有任务成功会重置计数，用例永远触发不了 | 用例失败后分析调度顺序 | 调整用例阈值与故障组合，使其真实覆盖熔断路径 |

## 4. 刻意约束 AI 的设计决策

- **数字只来自工具与本地计算**：LLM 摘要中的每个数字都要通过 `verifyNarrative` 与被引证据比对，否则整段弃用。
- **演示数据不冒充真实数据**：演示值为人工构造，页面、报告、证据三处标注；资讯/宏观在演示模式下只返回占位并计为“缺失”，不编造新闻或宏观数值。
- **不确定优先**：证据缺失/过期/冲突/失败时，引用它的结论自动降级为“不确定”（`gradeClaims`）。
- **合规三道关**：输入改写/拒绝 → 结论分级 → 输出审查（违规表述会被移除并记录）。
